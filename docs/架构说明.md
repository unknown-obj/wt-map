## 2. 模块职责

### 2.1 `server.js`

| 组成 | 职责 | 关键实现 |
|---|---|---|
| 静态托管 | 返回 `index.html` | 按扩展名设置 `Content-Type`，全部 `no-cache` |
| API 代理 | `/api/<name>` → `:8111/<name>.json` | `http.request` 流式转发，不缓冲大响应 |
| 特殊路由 | `/map.img`、`/hudmsg` 带查询串原样透传 | 保留 query string |
| 状态接口 | `/api/status` | 记录最近 15 秒内的客户端 IP，枚举内网地址 |
| 健壮性 | 端口占用时静默退出；未捕获异常写日志 | `EADDRINUSE` → `exit(0)` |

### 2.2 `index.html`（前端）

| 子系统 | 位置 | 说明 |
|---|---|---|
| 轮询调度 | `poll()` / `instLoop()` | 地图 10 Hz、仪表 10–20 Hz，互不阻塞 |
| 数据整形 | `toArray()` / `kindOf()` | 统一 `x/y` 与 `sx/sy`，映射图标类别 |
| 状态机 | `haveData` / `inBattle` / `linked` / `demoOn` | 决定显示真实数据、归零还是演示 |
| 平滑 | `smp` 对象 + `kk2` 系数 | 俯仰/滚转/航向/表速/高度 |
| 姿态仪渲染 | `drawPFD()` | 天地线变换、刻度弧、俯仰梯、三条带、读数 |
| 地图渲染 | `drawMap()` | 底图、网格、单位、战区、箭头、播报 |
| 断联 UI | `updateLinkUI()` | 每帧检查，成功/失败都生效 |
| 校准 | `cal` 对象 + `localStorage` | 俯仰/滚转偏移、单位、地图平移 |

## 3. 数据流时序

```
t=0ms     poll()  ── GET /api/map_obj.json ──▶ 8111
t=20ms    ◀── 13 KB JSON ── items = parse()
t=20ms    instLoop() ── GET /api/state + /api/indicators（并行）
t=45ms    ◀── 0.6 KB + 1.5 KB ── st8 / ind8 更新
t=45ms    haveData = (st8.valid === true && typeof st8['IAS, km/h'] === 'number')
t=50ms    drawMap()   （每 ~90ms 一次）
t=16.7ms  drawPFD()   （每帧，读平滑后的值）
```

所有请求都是 `await` 后立刻处理，**没有排队、没有背压**：
上一轮未返回时下一轮照样发（超时 2.5 s 自动放弃），避免一次卡顿拖垮整条链。

## 4. 渲染管线

### 4.1 姿态仪坐标系

```
(0,0) ─────────────── (W,0)
  │  ┌─────────────┐
  │  │  天空/地面   │  ← 以 adiW × adiH 为裁剪区
  │  │   天地线     │  ← 先 translate(pitch) 再 rotate(-roll)
  │  └─────────────┘
```

绘制顺序：

1. 天空/地面两色矩形（超出裁剪区绘制，保证旋转时不露边）
2. 天地线 + 俯仰刻度（随姿态变换）
3. 滚转刻度弧（**固定**，不参与变换）
4. 固定飞机符号
5. 左右速度/高度带、底部航向带、读数行
6. 覆盖层：节流阀、断联文字、演示水印

### 4.2 地图坐标

```
归一化 (0..1) ──×── side ──+── origin ──▶ 屏幕像素
              GX(g,x) = g.ox + x * g.side
              GY(g,y) = flipY ? g.oy + (1-y)*g.side : g.oy + y*g.side
```

`side` 由 `min(宽,高) - padding` 乘以缩放系数得到，保证地图是正方形、不变形。

### 4.3 箭头（自身）

以多边形**面积质心**为旋转中心：

```
顶点：(0,-26) (10,10) (0,4) (-10,10)
质心 ≈ (0,-4)  → 绘制前 translate(0, +4) 对齐
```

旋转角 = `compass`（度），北为 0，顺时针为正；`flipY` 时取负。

## 5. 关键设计取舍

| 决策 | 备选 | 为什么选它 |
|---|---|---|
| 中间加 Node 代理 | 平板直连 8111 | 8111 只绑回环，局域网上不可达 |
| 前端 Canvas 渲染，不传视频 | 截屏/推流 | 带宽低两个数量级；文字清晰；可交互 |
| 无框架、单文件 | React/Vue + 打包 | 零构建、零依赖，复制即用；单文件便于分发 |
| 浏览器端平滑 | 服务端插值 | 不增加游戏端请求；延迟可控可调 |
| 地图与姿态仪分开限帧 | 统一 60 fps | 低端平板 CPU 有限，把预算给会动的姿态仪 |
| USB 走 `adb reverse` | 自建 TCP 桥 | 无需额外程序，系统自带 adb 即可 |
| `valid` 作为唯一可信判据 | 判断字段是否为空 | 字段可能残留上一局数值，只有 `valid` 可靠 |
| 断联 UI 由渲染循环驱动 | 请求回调驱动 | 服务完全挂掉时也能正确显示 |
