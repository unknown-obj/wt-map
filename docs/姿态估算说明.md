# 姿态估算（AHRS EST）说明

> 本文档记录本项目在「部分机型无姿态数据」时采用的替代方案。
> **思路与算法参考了 [WarThunder-8111-HUD](https://github.com/A-common-Chinese/WarThunder-8111-HUD) 项目（作者：缩写ACC）的 AHRS EST 模式，在此致谢。**

---

## 一、为什么会需要它

游戏 2.59.0 之后，部分较新机型的 `/indicators` 接口不再输出姿态字段：

```
aviahorizon_pitch   俯仰
aviahorizon_roll    滚转
bank                坡度
```

实测字段数差异很大：

| 机型 | 字段数 | 姿态 |
|---|---|---|
| J-11 | 66 | ✅ |
| MiG-29M | 54 | ✅ |
| MiG-35 | 30 | ❌ |
| JF-17 | 30 | ❌ |
| Z-10A（直升机） | 15 | ❌ |

没有姿态，姿态仪就只能是平的。与其显示一个"假的地平线"，不如：

1. **能算就算**（EST 模式），并明确标注"估算"；
2. **算不准的部分不显示**（本项目的坡度不画指针，只给带杆提示）。

---

## 二、算法

### 2.1 俯仰

```
航迹倾角 γ = asin(Vy / TAS)
机头俯仰 = γ + 迎角 AoA
```

- `Vy`：垂直速度（m/s），来自 `/state`
- `TAS`：真空速（m/s），来自 `/state`
- `AoA`：迎角（度），来自 `/state`

随后做一阶低通滤波（本项目 τ ≈ 0.25 s），防止抖动。

**实测结论：俯仰基本可用。**

### 2.2 坡度

```
坡度 = atan(TAS × 航向变化率 / g)
```

- `航向变化率`：取约 1.4–1.6 秒窗口的 `compass` 趋势，**不逐帧差分**（噪声太大）
- 限幅 ±80°
- 绝对值小于 6° 视为 0，避免平飞抖动

**为什么不用 `acos(1/Ny)`**：该式只在「稳定水平转弯」成立，
筋斗或大 G 时会把平飞的飞机算成 80° 坡度。

**实测结论：坡度不可靠。** 平飞带坡度但不转弯时读数为 0，
大机动时误差更大。因此本项目**不显示坡度数值与指针**。

### 2.3 没有罗盘的机型

改为积分滚转角速度 `Wx`，并做缓慢回正（本项目衰减系数约 0.25/s）。

### 2.4 置信度

```
|Ny - 1| > 4  →  判定为大机动，置信度降到 0.35
```

界面表现：

- 正常：绿色 `EST`
- 低置信：黄色 `EST?`

## 三、本项目的界面处理

| 状态 | 显示 |
|---|---|
| 有真姿态字段 | 正常姿态仪（蓝天黄土 + 滚转弧 + 指针），无角标 |
| 无姿态、可估算 | **黑底 + 荧光绿俯仰刻度 + 飞机符号**，右上角绿色 `EST` |
| 无姿态、坡度超过 6° | 额外显示 `← 左 急带杆` / `右 急带杆 →` |
| 大机动 | 角标变黄色 `EST?` |
| 连 `/state` 都没有 | 保持上一帧 2 秒，之后显示「本机无姿态数据」 |

**关键取舍**：

- EST 模式**不画天空/地面颜色**——颜色是"可信姿态"的视觉承诺，估算担不起；
- 坡度**不画指针、不给数值**，只给方向提示；
- 角标必须显眼，不能让人误以为是真仪表。

## 四、已知误差

| 项 | 误差来源 | 量级 |
|---|---|---|
| 俯仰 | Vy/TAS 的采样延迟、AoA 滤波 | 1–3° |
| 坡度方向 | 航向变化率的趋势判断 | 大体正确，可能滞后 |
| 坡度数值 | 协调转弯假设不成立 | 不可用 |
| 整体延迟 | 1.4 s 窗口 + 滤波 | 0.3–0.6 s |

**无法判断正飞还是倒飞**——这是所有基于 `/state` 的估算方案的共同缺陷。

---

## 五、校准

| 问题 | 处理 |
|---|---|
| 俯仰有固定偏差 | 用界面上的「仪校准 → 俯仰 ±」修正 |
| 带杆提示方向反了 | 用「滚转反向」开关修正 |
| 完全不想看估算 | 设置里可关闭（后续版本提供） |
